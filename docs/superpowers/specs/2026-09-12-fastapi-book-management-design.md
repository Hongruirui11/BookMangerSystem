# 教学型图书管理系统设计

## 1. 目标

从一个空项目开始，构建一个简单的前后端分离图书管理系统，用于学习 FastAPI 的核心开发方式，并让每个指定知识点都有可运行的示例。

## 2. 技术方案

- 前端：Vue 3 + Vite
- 后端：FastAPI + Uvicorn
- 数据访问：Tortoise-ORM
- 数据库：MySQL
- API 数据模型：Pydantic
- 版本控制：Git；后续创建新的 GitHub 远程仓库并同步

前端和后端分别运行开发服务器。前端通过 HTTP 调用 FastAPI 接口；后端通过 CORS 允许本地前端开发地址访问。数据库连接信息通过环境变量配置，不提交真实密码。

## 3. 功能范围

第一版只实现图书管理：

- 查看图书列表
- 按书名或作者查询
- 查看图书详情
- 新增图书
- 编辑图书
- 删除图书

图书字段为：`id`、`title`、`author`、`isbn`、`publisher`、`published_year`、`description`、`created_at`。

不实现登录、权限、借阅流程、文件上传、复杂分页和生产部署配置。

## 4. FastAPI 知识点落点

后端按职责拆分模块，并通过 `include_router` 完成路由分发：

- `/api/books`：列表、新增
- `/api/books/{book_id}`：详情、编辑、删除
- `/api/books/search`：查询示例

接口使用 Pydantic 请求模型和响应模型，展示路径参数、查询参数、请求体、状态码和错误响应。单独提供一个使用 `Request` 对象的示例接口，读取请求方法、URL、客户端信息或请求头。

静态文件通过 `/static` 挂载；模板文件使用 Jinja2 渲染一个简单的欢迎页或接口说明页。这部分作为教学示例，与 Vue 主页面并存，不承担核心业务页面职责。

## 5. 前端结构

Vue 页面保持简单，包含：图书列表/搜索区域、图书表单、编辑与删除操作、错误提示和加载状态。通过一个轻量 API 模块集中封装后端请求，避免组件直接散落请求细节。

## 6. 数据流和错误处理

页面操作 → Vue API 模块 → FastAPI 路由 → Tortoise-ORM → MySQL → JSON 响应 → Vue 更新状态。

后端对不存在的图书返回 404；请求字段不合法由 Pydantic 返回 422；数据库或服务异常返回统一的错误结构并记录日志。前端展示可理解的错误提示，不吞掉请求失败。

## 7. 教学交付方式

按递进顺序实现并配套 README：

1. 项目目录、虚拟环境和依赖
2. FastAPI 最小应用与路由分发
3. MySQL 连接和 Tortoise-ORM 模型
4. 图书 CRUD 接口
5. Request、静态文件和 Jinja2 模板
6. Vue 页面与 API 联调
7. Git 提交、GitHub 远程仓库和运行说明

README 说明 MySQL 建库、环境变量、前后端启动命令、接口地址和每个知识点对应的文件位置。

## 8. GitHub 同步约定

本地仓库使用清晰的初始提交，并加入 `.gitignore`，排除 Python 虚拟环境、Node 依赖、构建产物、环境变量文件和数据库临时文件。GitHub 远程仓库创建后配置为 `origin`，推送主分支；真实密钥只保留在本地 `.env` 中。
